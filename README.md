# PersonalAIFitness · 个人训练

面向个人使用的原生 iPhone 训练记录项目。SwiftUI + SwiftData，本地优先；当前为 **0.6.2 全量动作示范接入批次**，不是完整需求已交付，也没有完成真机验收。

## 0.6.2 全量动作示范

- 接入free-exercise-db-api全部317个来源动作和593个男女示范版本；72个明确同变式映射既有ID，245个独立变式新增，总467个动作，原222个动作定义和ID保留。
- 全部593段完整示范短片、对应封面和真实连续帧GIF随包离线提供；动作详情可选择男/女示范。原42组短片及旧图示保留来源和文件。
- 新增动作中文名称、器械和肌群；教学保留上游英文原文并明确标记，尚未完成全部文字的中文专业审校。新变式不靠名字自动加入AI规则池，全部可用于手动计划和记录。
- 视频接入由本人明确确认，保留维护者的视频来源自述；不宣称已独立核实视频MIT授权。代码/元数据MIT归因与每个媒体的URL、源文件和成品摘要分别保存。
- 源JSON、显式映射和生成器可追溯；最终构建及可播放性以对应Actions实际结果为准。

## 0.6.1 访谈抽取恢复和动态素材

- 222个动作，42组有授权的离线H.264短片与真实连续帧GIF，另有18组静态图示。仍有缺素材动作；短片不冒充完整教学课程。
- 可见动作卡片播放GIF预览；减少动态效果或后台时显示静态封面。
- 数字单位、器械数组等明确表示可规范化为待确认候选。坏的可选抽取不再丢弃整轮有效问题；未知值不写档案，矛盾候选需澄清，成年仍须本人明确回答。
- 补壶铃器械与明确适用的候选；不把壶铃无条件视作哑铃。原始访谈和已确认计划保留。实际验证以本提交Actions结果为准。

## 0.6.0 月历历史、动作库和深入建档

0.6.0交付时目录有217个动作，39个有离线示范媒体（11组短片/GIF、28组静态图示）。4组无法确认对应变式的图片已解除展示绑定，保留来源归因供审查。完整教学视频仍未覆盖全库。

- 底部历史采用训练月历，按本地日期展示真实记录、状态及明确口径的实际量，点日期看当日多场训练；无记录保持空白。
- 扩充带稳定ID的中文动作与有逐项来源/许可的离线图示；图示、示范短片与尚缺的完整教学明确区分，来源随动作可查。
- 建档支持自由介绍、补充回答和同一主题的细节追问，保存后可续聊；结构化推断仍须本人确认。深度回答参与个性化计划的输入，不只是聊天展示。
- 访谈JSON模式、无损格式兼容和受限纠正；截断、空内容、拒绝与格式问题分别报告，不在错误信息泄露服务原文或密钥。
- 实际测试与构建结果以本提交的Actions为准。训练/月历截图专用验证数据只在DEBUG隔离内存中使用，带可见标记，不写正常数据库。

## 0.5.0 原生视觉与原库清理

- 蓝白视觉系统、图像优先动作库、紧凑首页、结构化教练入口、计划/历史分段、训练输入与休息停靠区；支持明暗与大字体自适应。缺数据保留未知，不显示假成绩或恢复总分。
- 首页主要教练入口直接进入详细建档访谈；动作教学使用已有授权素材，缺素材明确标记。
- 启动失败页与设置均可进入「彻底删除原数据库」。展示旧默认库及配套文件清单；须明确确认后物理清理主库/WAL/SHM/journal和本App原库自动恢复副本，核验残留；不自动备份或静默删除。
- 当前独立Training.store、手动导出的备份、AI密钥和Apple健康数据保留；旧容器在销毁前停止后续写入，失败不报告成功。实际手机删除尚待用户安装后主动执行。
- DEBUG截图的训练场景使用独立内存容器，并显示验证数据标记；不会为正常用户预置计划或训练成绩。
- 仍未新增：安全的训练中动作替换、自动渐进/长期周期建议生成、个人生理基线、历史更正、全部动作的完整教学视频。

## 0.4.3 本地存储路径保护

- 新安装使用 Application Support/PersonalFitness/Training.store，避免占用通用 default.store。
- 启动先只读查找常用目录中四层以内的存储元数据。若只找到一个健身库，继续打开原位置；真正迁移与内容校验仍由原规则执行。多个候选、扫描不完整或打开失败均停止，不自动换空库。
- 默认路径中的不匹配模型不会交给健身迁移器，不移动、删除、覆盖或合并原文件；启动诊断增加候选库的相对位置与模型清单。
- 找不到健身库时须继续排查旧计划的位置。用户可经单独确认选择独立新库，界面持续说明旧计划尚未恢复；这不是数据恢复。
- 新增不匹配缓存模型、已有历史发现、旧库延用、歧义、损坏及扫描边界测试。实际设备上旧数据是否恢复需另行验证。

## 0.4.2 启动诊断

- 启动无法打开本地数据时，可复制或导出诊断 JSON：版本、系统、错误代码及嵌套错误、存储文件状态、模型标识和哈希。不会导出档案、训练、健康明细、任意错误描述或 API 密钥。
- 不自动清空数据库、不换库、不在旧库上尝试其他 schema。对照模型只在独立缓存目录生成空库，读取元数据后删除该临时目录。
- CI 增加历史发布源码编译后的跨进程写库、升级、再次冷打开探针；另有 V3→V4 非空逻辑记录保留测试。探针只用合成测试标记，不是用户训练数据。
- 这是诊断能力，不能据此宣称某台设备的升级错误已修复。设备故障仍需该设备导出的诊断来定因。

## 当前范围

- 手动创建/修订计划，明确确认后产生新版本，保留旧版本。
- AI 制定起始周计划：明确目标、经验、训练日、预算、器械与安全信息；本地规则生成可行候选，AI 从候选中选择解释；七天对比后明确确认才生成每日计划与每周排程。支持明确标记的离线本地规则模式。
- 多手动计划切换、可恢复的删除；删除保留版本、训练历史及进行中执行快照，恢复不自动生效。首页显示今天安排，休息日不会拿别的训练日冒充今天。
- 力量、有氧、徒手记录；热身/正式组、重量/次数/时长/距离、可选 RPE/RIR、上次数据、复制与备注。
- 逐组显式保存、休息计时、暂停/恢复、提前结束与重开后的进行中会话入口。
- 本地历史与基础统计、自定义动作；初始库没有虚构的个人训练或健康数据。
- 扩展中文动作库、英文/别名搜索、肌群/器械筛选、收藏、动作步骤/常见错误与部分有许可的离线示范短片。
- 可配置的 OpenAI 兼容 Chat Completions：自有接口/模型/Keychain密钥，每次先预览数据再明确发送；基于真实记录与本地动作资料问答，保守减量建议经校验、对比和确认才产生新计划版本。
- 加密逻辑备份/恢复：PBKDF2-SHA256 + AES-GCM，恢复前验证与保护副本。
- **AI 教练建档访谈**：教练逐轮结构化追问，每项档案都带来源（本人回答／本人确认／健康数据／待确认推断／未知）；AI 的推断必须由本人逐条确认后才参与制定计划；成年与运动限制必须由本人明确回答，不被默认。
- **按档案组合首版计划**：AI 只在本地允许的动作池内选择，组数、休息、时间再由同一套规则复核；未知能力不生成公斤数。生成结果仍走"看差异 → 本人确认 → 生效"的原流程。
- **每日跟进**：训练前记录精力/酸痛/疼痛/可用时间，训练后记录主观用力与感受；客观组数时长由程序计算，用户不能改写；没回答记为"未回答"，不当成"没问题"。
- **Apple 健康真实读取**：步数、静息心率、HRV（SDNN）、睡眠、活动能量、体重、运动时长、心肺适能；按类型保存增量锚点，样本时间与读取时间分开显示；空结果报"暂无样本"，不谎称权限被拒。
- **身体状态评估**：安全、恢复证据、表现趋势、可信度、今日建议、依据六部分分开输出，**不合成恢复分**；缺数据时只可能给"保守或先收集"，不会给"状态良好"。
- **调整与复盘**：生成保持或保守临时减量建议，确认后的临时方案用于一次真实训练快照，长期计划不变；指纹改变或跨日时旧建议失效。长期修改的版本和决定使用同一事务，但自动渐进/周期建议生成仍未实现。周月复盘使用确定性统计并明确数据缺口。

**尚未实现**：长期周期化与自动进阶、医学限制的个体适配、全库 GIF 与每个动作的完整教学视频、档案修订时间线、历史更正与完整趋势图。自动制定仍只面向本人明确确认已成年、无已知限制、今日无痛的成人；有疼痛或限制时不自动制定。未提交输入不能保证在强制终止后保留。

**本批验证层级**：以本提交对应的 Actions 实际结果为准，源码或静态检查不能代替编译与 XCTest。**未做**真机签名安装、真实 HealthKit 读取、真实 AI 服务联通验证。编译和模拟器测试通过不等于这些已验收。

## 构建与测试

目标 iOS 27.0；仓库自带一个纯 Swift 核心包、iOS App、App tests 和确定性工程生成脚本，无第三方运行依赖。

```sh
python3 scripts/generate_project.py
python3 scripts/check_source.py
swift test --package-path Packages/FitnessCore
xcodebuild test -project PersonalFitness.xcodeproj -scheme PersonalFitness \
  -destination 'platform=iOS Simulator,id=<available iOS 27.0 simulator UDID>'
```

GitHub Actions 固定 Xcode 27.0，依次运行结构检查、核心测试、iOS Simulator 测试和 iPhoneOS 构建，全部成功后打包 **未签名 IPA**。是否已通过，以具体 workflow run 为准；仅有源码和结构检查不代表构建成功。

在成功的 Actions run 中下载 `PersonalFitness-unsigned-ipa`。需要使用自己的证书与描述文件签名后安装，默认 Bundle ID 为 `com.personalfitness.private`；HealthKit 要求最终签名/profile 匹配其 entitlement。CI 通过不等于手机安装或健康数据读取已验证。详见 [试用说明](Documentation/TRYOUT.md)。

## 0.4.1 流程修复

访谈后的计划实际请求模型选择允许池内的动作，再由独立规则确定剂量并校验。重新进入访谈保留已确认档案；临时调整用于一次真实训练；健康样本按 UUID 合并增删；疼痛未知与过期数据不当成正常恢复。

自动渐进/周期建议生成及个人生理基线仍未实现。详见[教练实际流程与验证边界](Documentation/AI-COACH.md)。
