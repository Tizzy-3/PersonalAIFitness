# 当前功能与验收边界

0.2 是在 0.1 记录基础上补齐动作库与 AI 接口的开发批次。具体编译与测试结果以提交对应的 Actions run 为准，不能以此表代替运行证据。

| 原需求 | 当前实现 | 尚缺内容 |
|---|---|---|
| 首页 | 手动计划、逐动作入口、恢复训练、档案/健康/教练入口 | 周期排期、真实身体状态摘要、长期教练建议摘要 |
| 档案 | 基本资料、目标、经验、器械、时间、运动限制，未知可留空 | 完整首次引导、偏好/场地、修订时间线 |
| 动作库 | 固定ID的中文常用目录、英文/别名、筛选搜索收藏、自定义、步骤/错误/替代进阶、部分离线署名媒体、加入当前计划需确认 | 全库GIF与完整教学视频、教练对内容正确性逐项验收 |
| 训练 | 力量/有氧/徒手记录、热身/正式组、可选RPE/RIR、上次/复制、暂停恢复、提前结束、重开会话 | 历史更正、更完整的动作替换与复杂训练编排；未提交输入不保证强退保存 |
| Apple 健康 | 用户主动读取步数/静息心率/体重，显示来源/时间与空数据边界 | 睡眠/HRV/运动等其余类型，历史/增量/去重/删除/基线 |
| 身体状态 | 尚未实现 | 独立安全、恢复证据、表现、可信度、建议与依据引擎 |
| 科学计划 | 人工计划编辑与版本确认 | 独立规则引擎、按约束初次生成、周期、进阶与中断适应 |
| AI 教练 | 可配置HTTPS Chat Completions、模型、Keychain密钥、测试连接、发送前实际JSON预览；基于近10次记录和28天程序统计及本地动作资料回答；历史保存；已有计划保守减量的对比/拒绝/确认 | 完整健康/状态证据输入、自动计划/替代候选、月度长期复盘全量统计、其他协议适配 |
| 统计 | 基础次数/组数/时长，AI只解释程序统计 | 完整单动作/有氧/体重/状态趋势与周期执行分析 |
| 数据保护 | SwiftData版本迁移、计划历史、加密备份恢复、教练决定与收藏进入备份；密钥不进入备份 | 签名和真机覆盖升级/备份恢复仍需验收 |

## 本批次先验证这些操作

1. 升级前先导出原数据备份；保留相同 Bundle ID 覆盖安装，勿卸载清数据。
2. 动作库搜索熟悉动作，切换类型/肌群/器械、收藏；查看有素材项目的离线图片或短片和署名，再确认加入计划。
3. 在“教练 → 配置AI接口”填写最终HTTPS地址、模型和本机Key，点明确的连接测试；这会调用你的服务，但不发送个人资料。
4. 提问并预览实际数据；明确发送后获得真实服务回答，查看本地记录与依据。接口/格式不兼容应明确报错，不显示预设回答。
5. 已有计划且无档案运动限制时尝试保守减量，先看逐项对比；拒绝保留原计划，明确确认才生成新版本。改变档案/训练/计划后旧建议须失效。
6. 导出再恢复备份，核对教练记录与收藏；AI Key恢复后按本机配置重新输入。

## 验证分层

协议测试使用明确命名的URLProtocol夹具，不代表供应商连通或模型建议正确。CI编译/模拟器测试不能证明自行签名、真机安装或Apple健康权限有效。没有实际自有API调用证据前，不宣称所有OpenAI兼容服务都已验证。
